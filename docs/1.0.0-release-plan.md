# 1.0.0 发布修复计划

目标：在发布 `1.0.0` 前修复会话定位、消息完整性和消息顺序问题，并让搜索结果、支持范围和发布说明与实际行为一致。

## 实施顺序与验收标准

1. **稳定编号引用**
   - `#N` 始终解析为用户上一次看到的列表项，不因后续全量扫描或仓库切换改变。
   - 增加跨仓库回归测试，同时保留 `agent:id`、ID 前缀和标题片段解析。
2. **保留 Codex 的真实重复轮次**
   - 只合并 Codex 同一消息在 `response_item` / `event_msg` 中的相邻双份记录。
   - 不相邻的相同用户输入必须全部保留，并正确计入 `turns`、`preview` 和 `session_inputs`。
3. **按 Cursor 原始顺序读取消息**
   - 优先使用 `composerData.fullConversationHeadersOnly` 的 `bubbleId` 顺序。
   - 有头部索引时只读取当前主线，排除 KV 中残留的废弃分支；缺少索引时采用稳定回退。
   - `turns`、`bubbles`、`tail`、`last`、摘要和自动交接复用同一主线定义。
4. **扩展会话搜索**
   - `ass search` / `searchSessions` 同时搜索标题、最近消息预览和对话正文，并标明命中来源。
5. **校准支持范围**
   - 明确 Claude Code、Codex、Cursor、OpenCode 是内置解析器。
   - Kiro、Trae、Windsurf 等属于检测与自定义适配范围；自动交接原生安装目前仅覆盖 Claude Code 和 Cursor。
6. **发布准备**
   - 包版本更新到 `1.0.0`，同步 lockfile、CHANGELOG 和中英文 README。
   - 通过类型检查、全量测试、打包清单检查和真实 Cursor/Codex 数据只读验收。

## 发布边界

- 不修改任何 agent 的原始会话、标题库或图片文件。
- 不自动安装钩子；维护者于 2026-10-15 授权提交、推送代码并发布 npm 1.0.0 和 Git 标签。
- 已有交接快照和任务目标不追溯改写。
